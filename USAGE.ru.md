# xc_export — Руководство оператора

*Языки: [English](USAGE.md) · **Русский** (этот файл)*

Инструмент для того, кто принимает треки пилотов на соревнованиях. Он скачивает треки полётов
(IGC) за выбранный день с **xcontest.org** и складывает их с готовыми именами в одну папку для
вашей программы учёта. Также умеет собирать треки, присланные пилотами через Telegram-бота (из
локальной папки или с сервера по SFTP).

---

## 1. Что нужно

- **`xc_export.exe`** (один файл) — либо исходники на Python с виртуальным окружением.
- **`xc_export_conf.ini`** — настройки (должен лежать в одной папке с exe).
- **`xc_cookie_1.txt`** — ваша сессия входа на xcontest (создаёте сами, см. §4).
- **Список участников** `.xlsx` — список пилотов на мероприятие (необязательно, но обычно есть).

> Положите `xc_export.exe`, `xc_export_conf.ini` и файлы `xc_cookie_*.txt` **в одну папку** и
> запускайте exe **из этой папки**. При двойном клике из другого места конфиг не найдётся.

Запуск из Python вместо exe:
```
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

## 2. Ежедневный порядок работы (кратко)

1. Откройте `xc_export_conf.ini`, задайте **`date`** — день соревнований (`ГГГГ-ММ-ДД`).
2. Обновите cookie входа в `xc_cookie_1.txt` (§4) — делается один раз, повторять только когда
   сессия протухнет.
3. Запустите `xc_export.exe` (или `xc_export.cmd`).
4. Треки появятся в папке результата: `track_dir\<date> <date_name>\` (§7).

---

## 3. Как выбираются пилоты

Для заданных **соревнования** (`src`), **дня** (`date`) и, опционально, **страны** (`country`)
инструмент запрашивает у xcontest полёты за этот день и скачивает трек, если **имя пользователя
xcontest** пилота есть в колонке **`Login`** файла участников.

- Если список участников **не задан**, скачиваются **все** полёты по `src`/`date`/`country`.
- Треки из Telegram-бота сопоставляются по колонке **`tg_username`** (§8).

## 4. Получение cookie xcontest (самый важный шаг)

Вход выполняется путём переиспользования сессии из вашего браузера (xcontest теперь требует
проверку Cloudflare «я не робот», которую проходит только настоящий браузер). Сессию копируют
один раз:

1. В **Chrome или Edge** откройте `https://www.xcontest.org` и **войдите** (пройдите проверку
   Cloudflare).
2. Нажмите **F12** → вкладка **Network** (Сеть).
3. Нажмите **F5**, чтобы перезагрузить страницу.
4. Кликните первый запрос к `www.xcontest.org` (например, `world/en/`) в списке.
5. Найдите раздел **Request Headers** (Заголовки запроса), заголовок **`cookie`**.
6. Скопируйте его **целиком** (длинная строка вида `PHPSESSID=...; other=...`).
7. Вставьте в файл **`xc_cookie_1.txt`** (одной строкой) и сохраните.

Готово — инструмент читает этот файл при запуске. Когда сессия протухнет, появится сообщение
`HTTP 403 — session expired`; просто повторите эти шаги и обновите файл.

> **Два логина?** Можно задать несколько аккаунтов (см. `[ACCOUNT:*]` в §6), у каждого свой
> cookie-файл. Если xcontest ограничит один по частоте запросов, инструмент сам переключится на
> следующий.

## 5. Список участников (.xlsx)

Обычная таблица Excel, одна строка на пилота. Важны **имена** колонок (с учётом регистра):

| Колонка       | Назначение                                                                    |
|---------------|-------------------------------------------------------------------------------|
| `Login`       | **Имя пользователя xcontest** — по нему выбираются полёты для скачивания.      |
| `tg_username` | **Имя в Telegram** — для сопоставления треков из Telegram-бота (§8).           |
| `Number`, `Name`, … | Любые дополнительные колонки — можно вставлять в имя файла (§6, `[XLSX-…]`). |

Каждая колонка доступна в имени выходного файла как `[XLSX-<ИмяКолонки>]`
(например `[XLSX-Name]`, `[XLSX-Number]`, `[XLSX-Login]`).

### Альтернатива: FSDB (FScomp) вместо .xlsx

Вместо `attendence_list_file` можно указать файл **FSDB** из FScomp параметром `fsdb`. Имя
пользователя xcontest берётся из кастомного поля участника **`xcontest login`** (имя настраивается
через `xcontest_login_field_name`). В качестве номера используется `id` участника, в качестве
имени — `name` (поэтому те же токены `[XLSX-Number]` / `[XLSX-Name]` работают).

Подготовка FSDB (один раз):

1. Укажите `fsdb=<путь>` и `fsdb_update=true`, запустите один раз. Инструмент добавит пустое поле
   `xcontest login` каждому участнику, у кого его нет, и сохранит файл.
2. Откройте FSDB в FScomp и заполните у каждого пилота **xcontest login**. Сохраните.
3. Поставьте `fsdb_update=false` и запускайте как обычно — треки сопоставленных пилотов скачаются.

Примечания: при заданных обоих `fsdb` имеет приоритет над `attendence_list_file`. Сопоставление
треков Telegram-бота (§8) требует колонку `tg_username` из `.xlsx` и из FSDB недоступно.

## 6. Настройки — `xc_export_conf.ini`

### `[MAIN]`

| Ключ | Обяз. | Значение |
|------|-------|----------|
| `src` | да | Путь соревнования, напр. `world/2026`. |
| `date` | да | День соревнований, `ГГГГ-ММ-ДД`. **Меняйте каждый день.** |
| `date_name` | нет | Суффикс к имени папки результата (напр. `TrainDay`). |
| `country` | нет | Фильтр по стране, напр. `KZ`. Без него — все страны. |
| `track_dir` | да | Базовая папка для сохранённых треков. |
| `attendence_list_file` | нет | Путь к файлу участников `.xlsx`. |
| `fsdb` | нет | Путь к файлу FSDB (FScomp) — альтернатива `.xlsx` (см. §5). |
| `fsdb_update` | нет | `true` = добавить пустое поле `xcontest login` участникам без него и сохранить FSDB. По умолч. `false`. |
| `xcontest_login_field_name` | нет | Имя кастом-поля FSDB с логином xcontest. По умолч. `xcontest login`. |
| `igc_file_name` | да | Шаблон имени выходного файла (токены ниже). |
| `tracks_loaded_file_name` | нет | Файл прогресса, по умолчанию `tracks_loaded.json`. |
| `xc_max_flights` | нет | Макс. число полётов за день, по умолчанию `1000`. |
| `only_check` | нет | `yes` = только показать совпадения, ничего не качать. По умолч. `no`. |
| `key` | нет | API-ключ xcontest (встроен рабочий по умолчанию). |
| `lng` | нет | Язык интерфейса, по умолчанию `en`. |
| `log_level` | нет | `DEBUG` / `INFO` / `ERROR`. |
| `log_file` | нет | Дублировать лог в этот файл. |
| `tg_bot_dir` | нет | Папка с треками Telegram-бота (см. §8). |
| `tg_bot_mode` | нет | `local` (по умолчанию) или `ssh` (см. §8). |

**Токены шаблона имени** (`igc_file_name`):

- `[XLSX-<Колонка>]` — любая колонка из списка участников, напр. `[XLSX-Name]`, `[XLSX-Number]`.
- `[YYYY] [MM] [DD] [H24] [MI] [SEC]` — дата/время полёта (у Telegram-треков время `000000`).
- `[TYPE]` — `xcontest` или `tg`.
- `[LOGIN]`, `[XC_NAME]`, `[XC_CIVL]` — логин / имя / CIVL-id пилота (треки xcontest).
- `[TG_USERNAME]` — имя в Telegram (треки Telegram).

Пример: `[XLSX-Name].[YYYY][MM][DD]-[H24][MI][SEC].[TYPE].[XLSX-Number].igc`
→ `Alexander Fedorov.20260729-055200.xcontest.124.igc`

### `[ACCOUNT:*]` — один или несколько сеансов входа

```ini
[ACCOUNT:1]
cookie_file=xc_cookie_1.txt

[ACCOUNT:2]
cookie_file=xc_cookie_2.txt
```
У каждого аккаунта свой cookie-файл (§4). Нужен минимум один. При ограничении по частоте или
протухшей сессии инструмент переключается на следующий.

### `[SSH]` — только при `tg_bot_mode=ssh`

```ini
[SSH]
host=example.com
port=22
username=user
password=secret
```

## 7. Запуск и куда попадают треки

Запустите `xc_export.exe` (откроется консольное окно с логом). Результат складывается в:

```
<track_dir>\<date> <date_name>\
```
напр. `D:\Tracks\2026-07-29 TrainDay\`. Внутри — IGC-файлы и `tracks_loaded.json`, где
отмечено, что уже скачано. Поэтому повторный запуск за тот же день докачивает только **новые**
треки (можно спокойно запускать несколько раз в течение дня).

---

## 8. Треки из Telegram-бота (необязательно)

Если пилоты присылают треки через Telegram-бота, укажите в `tg_bot_dir` папку с этими файлами.
Инструмент смотрит в `tg_bot_dir/<date>/` и ожидает имена файлов в формате:

```
<дата>#<tg_username>#<исходное_имя_igc>
```

Файлы сопоставляются с пилотами по колонке **`tg_username`** списка участников и копируются в ту
же выходную папку с именем по вашему шаблону `igc_file_name` (`[TYPE]` = `tg`).

- **`tg_bot_mode=local`** — `tg_bot_dir` это папка на данном компьютере.
- **`tg_bot_mode=ssh`** — `tg_bot_dir` это путь **на сервере**; инструмент читает его напрямую
  по SFTP, используя доступы из `[SSH]` (монтировать диск не нужно).

## 9. Устранение неполадок

| Сообщение / симптом | Что значит и что делать |
|---------------------|-------------------------|
| `Cookie file "xc_cookie_1.txt" not found` | Создайте файл по §4, рядом с exe. |
| `... not a valid xcontest session (expired?)` | Cookie устарел — обновите (§4). |
| `Got HTTP 403 — session expired` | То же: заново скопируйте заголовок `cookie` в файл. |
| `Got list of flights: 0` | Нет полётов по `src`/`date`/`country` или неверная `date`. |
| `cannot find TG path: …` | Папки `tg_bot_dir/<date>` нет (в этот день нет Telegram-треков) — не страшно. |
| Ошибки подключения SSH | Проверьте в `[SSH]` host/port/username/password и путь `tg_bot_dir` на сервере. |
| Ошибка конфига `[SSH].host MUST be defined` | Указан `tg_bot_mode=ssh`, но секция `[SSH]` отсутствует/неполная. |

**О безопасности:** cookie-файлы и пароль в `[SSH]` — это секреты. Не передавайте их и не
коммитьте в публичный репозиторий.
